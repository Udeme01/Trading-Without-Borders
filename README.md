# Trading Without Borders — Site Scaffold

Next.js 15 (App Router) scaffold generated directly from the sitemap doc. It's
structure and design tokens, not finished pages — every section that needs
real copy is marked `{/* TODO */}`.

## Getting started

```bash
npm install
npm run dev
```

## Folder structure

```
app/                        Routes (App Router). One folder per sitemap page.
  layout.tsx                 Fonts, global <head> defaults, Header/Footer shell
  page.tsx                   PAGE 1 — Home
  robots.ts                  Generates /robots.txt
  sitemap.ts                 Generates /sitemap.xml
  discover/
    page.tsx                 PAGE 2 landing — role picker grid
    [role]/page.tsx           One template, 8 roles via generateStaticParams
  solutions/
    page.tsx                 PAGE 3 landing
    [slug]/page.tsx           One template, 7 solutions via generateStaticParams
  trade-intelligence/
    page.tsx                 PAGE 4 landing (search/filters go here)
    [category]/page.tsx       Category listing (e.g. /trade-intelligence/reports)
    [category]/[slug]/page.tsx  Article template
  podcast/
    page.tsx                 PAGE 5 landing
    [episode]/page.tsx        Episode template
  about/page.tsx             PAGE 6
  contact/page.tsx           PAGE 7

components/
  ui/          Small, dumb, reusable primitives: Button, Card, Badge, Container
  layout/      Header, Footer, Breadcrumbs — appear on every page
  sections/    Bigger reusable blocks: Hero, CTASection, NewsletterBanner
  content/     Cards tied to a data shape: ArticleCard, PodcastCard, RoleCard

lib/
  data/        Static content arrays (roles.ts, solutions.ts) — swap for a
               CMS/MDX source later without touching the pages that use them
  seo.ts       buildMetadata() — one place every page gets its <head> from
  utils.ts     cn(), formatDate()

types/         Shared TypeScript interfaces (Role, Solution, Article, PodcastEpisode)
```

**Why this shape:** every dynamic sitemap section (Discover roles, Solutions,
Trade Intelligence articles, Podcast episodes) is one route template driven by
a data array, not one file per item. Add a role or solution by adding one
object to `lib/data/roles.ts` or `solutions.ts` — the route, metadata, and
sitemap entry all pick it up automatically.

**What's still a stub:** Trade Intelligence articles and Podcast episodes
don't have a data source yet (no CMS decided). `lib/data/articles.ts` and
`lib/data/podcast.ts` are referenced but commented out in `sitemap.ts` —
uncomment once that content exists. Everything else — Home, Discover,
Solutions, About, Contact — is fully wired.

## Design system

No brand color yet, so the system leans on **contrast, type, and space**
instead — "quiet, but loud" comes from scale (huge serif headlines) and
restraint (strict black/white, sharp corners, hairline rules) rather than
color or decoration.

**Palette** — `tailwind.config.ts`
| Token | Hex | Use |
|---|---|---|
| `ink` | `#0A0A0A` | Text, primary buttons, borders on hover |
| `paper` | `#FAFAF8` | Background — warm off-white, not stark white |
| `line` | `#DEDDD6` | Hairline rules, card borders |

Swap in a brand color later by adding one token (e.g. `accent`) — nothing
else needs to change since components reference `ink`/`paper`/`line`, not
raw hex values.

**Type** — loaded in `app/layout.tsx`, three roles:
- **Fraunces** (display/serif) — headlines and pull quotes. It's a serif with
  real personality at heavy weights (near-Didone contrast, a bit of
  "wonk"/softness available via variable axes), which is what gives the
  Forbes-editorial feel without leaning on color. Used with restraint: only
  `h1`–`h3` and a few pull quotes, never body copy.
- **Geist Sans** (UI/body) — everything read at length: paragraphs, nav,
  buttons, forms. Neutral, high-legibility grotesk, free, built by Vercel
  specifically for Next.js (`geist` npm package, already in `package.json`).
- **Geist Mono** (data/labels) — the recurring "ticker" motif: eyebrows,
  category tags, dates, country/industry badges. Ties back to the subject
  matter (trade data, customs stamps, ledgers) instead of being decorative.

If you'd rather not add Fraunces, **Newsreader** or **Instrument Serif** are
close alternatives with the same editorial-serif feel; swap the import in
`app/layout.tsx` and the `--font-fraunces` variable name (or rename it).

**Signature move:** everything structural — eyebrows, tags, nav labels — is
uppercase mono with wide letter-spacing (`meta-label` class in
`app/globals.css`), boxed in hairline borders (`Badge.tsx`). It reads like a
trade ledger / customs stamp, which is the one aesthetic risk this scaffold
takes; keep it as the only recurring device rather than adding more.

## SEO — robots & sitemap

Both are generated by Next.js itself (App Router convention), no static
files needed:
- `app/robots.ts` → served at `/robots.txt`
- `app/sitemap.ts` → served at `/sitemap.xml`, currently includes Home, all
  static pages, all 8 Discover roles, all 7 Solutions. Article/episode
  routes are commented out until that data source exists — uncomment those
  blocks once `lib/data/articles.ts` / `podcast.ts` are real.

Before launch: update `SITE_URL` in `lib/seo.ts` (and the duplicate in
`app/layout.tsx`) from the placeholder to the real domain — everything else
(canonical URLs, OG tags, sitemap) derives from that one constant.
